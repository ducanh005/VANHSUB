# VANHSUB — Clean Windows acceptance handoff

**NOT READY. This kit has not passed installation on a clean Windows guest.** It is a local internal test artifact, not a published release. The installer is unsigned.

Use an independently controlled Windows VM with a fresh snapshot and a separate test account. Do not use the developer host or a personal Chrome profile as clean-install evidence. Record the guest Windows version, snapshot identity, baseline software and whether tests use a standard or administrator account.

1. Extract the entire kit into a path with spaces and Vietnamese characters, for example `C:\Kiểm thử VANHSUB RC`.
2. Read `acceptance-manifest.json`. Check the installer SHA256 using `Get-FileHash -Algorithm SHA256 -LiteralPath '.\VANHSUB Setup 1.0.0.exe'`; it must match the manifest. Record the unsigned-installer/SmartScreen outcome without changing host security policy automatically.
3. Optionally run `Capture-CleanWindowsBaseline.ps1 -SnapshotId '<fresh guest snapshot>' -IndependentCleanGuest` in the guest. The script only records baseline information; its output starts with installation PASS=false. If script policy blocks execution, collect the same read-only information manually under the guest's policy. Do not mark the environment clean solely from manufacturer strings or this switch.
4. Install interactively as the standard test user. Record UAC/permissions, install path, Start Menu entry and launch result. Do not install silently on the developer host. Test a custom Unicode/space install path if the installer supports choosing one; report unsupported choices accurately.
5. Launch without Node.js or a repository checkout. Check renderer/navigation/IPC, settings save/restart, project create/open/save, then import `Fixtures\Video mẫu.mp4` and `Fixtures\Phụ đề mẫu.srt`. Edit subtitles, save, close/reopen, export hardsub/softsub and check playback with FFprobe or another verified player.
6. Inspect native FFmpeg/FFprobe/Whisper availability in the installed resources. The bundled video has synthetic tone audio: **it cannot prove ASR recognition quality**. Use a separately approved known-speech fixture for actual Whisper recognition. Record first-run model download/network behavior explicitly; do not count missing model/Python prerequisites as a completed workflow.
7. OCR/Faster-Whisper/Demucs require separate Python packages/models; they are not bundled by this kit. Test the missing-dependency UI first, then document each installed prerequisite/version before testing the relevant workflow. Real cloud TTS/translation/Flow need a dedicated test configuration and a stated generation budget; do not include credentials in evidence.
8. On the guest, test cancel/rerun and close/restart during ASR, translation, TTS and FFmpeg. Preserve a completed output before each rerun, compare hashes after interruption, observe the actual app/worker PIDs, then check project/checkpoint recovery and duplicate-job rejection.
9. Check filesystem behavior with a writable Unicode project directory and an intentionally unwritable target. Keep test data in the guest; do not modify the host's files or permissions. Record denied-write errors and whether prior output survives.
10. Uninstall interactively. Verify process exit, shortcuts/install files, the documented disposition of test project/settings data, then reinstall and test recovery/upgrade behavior against an explicitly recorded previous version. Never delete user data to manufacture a clean baseline; restore the fresh VM snapshot for independent runs.

Copy `test-cases.json` to an evidence directory and fill only observed results. Keep Automated Test, Real Runtime, UI E2E, Live Provider, NOT TESTED and BLOCKED separate. Include installer hash, guest snapshot/baseline, native/provider versions, reproducible steps, screenshots/logs without secrets and any failure. No main merge or release is authorized by completing this checklist alone.
